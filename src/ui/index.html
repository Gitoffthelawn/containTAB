How containTAB decides

Rules match the URL hostname only. The protocol, path, query string, and hash are ignored.

Rules are not regular expressions. They use a small hostname pattern language so common cases stay readable.

Host patterns

example.com - exact hostname. Matches example.com, not www.example.com.

*.example.com - subdomains. Matches www.example.com and a.b.example.com, not example.com.

amazon.* - any suffix after the dot. Matches amazon.com, amazon.jp, and amazon.co.uk.

*.google.* - any subdomain and any suffix. Matches mail.google.com, not bare google.com.

@google - hostname contains this text anywhere. Matches www.google.com and mygoogle.net.

@.google. - a safer fragment with dot boundaries. Matches www.google.com, not mygoogle.com.

Multiple patterns

Use semicolons for OR logic inside one rule:

@youtube; *.yahoo; example.com

The rule matches when any token matches. Empty tokens are ignored, so extra spaces around ; are fine.

Specificity

When multiple rules match, the most specific matched token wins. Exact-looking patterns usually beat broad wildcards or fragments.

If two matching rules have the same specificity, the earlier stored rule wins.

What is not supported

No regex syntax: ^, $, [], (), and .* have no regex meaning.

No path matching: example.com/docs is not a URL path rule; rules should be hostnames or hostname patterns.

Containers

Rules assign URLs to shared containers by name.

If the container doesn't exist yet, it's created on first match.

Default Container

When no rule matches, containTAB can create an isolated default container based on the configured mode.

bytab creates a separate container per tab. Domain and hostname modes reuse names based on the URL host.

Lifetime

Until last tab: container deleted when last tab closes, rule kept for re-creation on next match.

Forever: container persists even with no tabs.

Container Lock

Once a tab enters a container, it stays there. Navigating to a different-rule URL opens a new tab.
